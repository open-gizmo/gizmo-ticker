# Agent instructions

For AI agents (Claude Code, Codex, Copilot and others) working on this repository. `CLAUDE.md` imports this file, so every agent reads the same rules.

## What this project is

Gizmo Ticker is a crypto price display: a Seeed Studio XIAO ESP32-S3 drives a MAX7219 LED matrix and scrolls the market data of the chosen coin, and a web app built into the firmware sets it up from the phone.

- `microcontroller/` is the PlatformIO firmware. It fetches the market data, drives the matrix, saves the settings and serves the web app and its API.
- `webapp/` is the Nuxt 4 web app, embedded in the firmware: the Ticker page (what the matrix shows), the API key, the device card and the Wi-Fi setup. It extends the [gizmo-common](https://github.com/open-gizmo/gizmo-common) web layer, and the mock device in `webapp/server/` answers like the firmware during development.

## Structure

- `src/main.cpp`: the entry point; starts logging, the settings, Wi-Fi, the web server and the matrix.
- `src/api`: fetches the market data and formats the scrolling messages (`market_data.*` and `market_refresh.*` are hardware-free and tested).
- `src/matrix`: drives the MAX7219 matrix (MD_MAX72xx and MD_Parola) and cycles the visible sections.
- `src/storage`: saves the display settings and the API key with `Preferences` (gizmo-common saves the Wi-Fi).
- `src/server`: the API routes for the settings and the API key, and the embedded web app (the Wi-Fi setup and device routes come from gizmo-common).
- `src/wifi`: gives the ticker's names to the gizmo-common Wi-Fi setup, and shows its status on the matrix.
- `src/config`, `src/serial`, `src/utils`: shared constants and state, the serial log, and small helpers.
- `src/webui`: generated by `npm run build:embedded`, never edited by hand.

## Working rules

1. Keep the split between firmware and web app clear: no device logic in the web app, no front-end behavior in the firmware.
2. Keep the module boundaries of `microcontroller/src/`: extend the right module instead of adding logic to `main.cpp`.
3. When a setting, route, payload or validation rule changes, update the firmware handlers, the mock device in `webapp/server/` and the web app together, and translate every new error ID.
4. Keep hardware-free logic free of hardware headers, and test it with `pio test -e native`.
5. Prefer small, hardware-aware changes: no blocking calls, no needless allocations, no broad refactors unless they are needed.

## With every change

1. **Write the changelog.** When a maker would notice the change (a feature, the web app, the hardware or wiring, the setup steps, a fix), add a line under `## Unreleased` in [CHANGELOG.md](CHANGELOG.md), in the same commit. Write it for the people who flash and use the gadget, not as a commit message: what changed for them, and what they need to do (flash again, rewire, set something up again). Internal changes (refactoring, tests, CI) need no line unless they change what the gadget does.
2. **Keep the docs in sync.** Update the README (and its screenshots in `docs/` when the web app looks different), and tell the user when the gadget's page on [opengizmo.dev](https://opengizmo.dev) needs the same change.
3. **Check it before calling it done.** Run the tests (`pio test -e native` in `microcontroller/`, `npm test` in `webapp/`) and the release build (`npm run build:embedded` in `webapp/`, then `pio run -e release`).

## Releasing

Follow "Releasing a new version" in the README. The version's notes must be moved from `## Unreleased` to a `## vX.Y.Z - YYYY-MM-DD` heading in CHANGELOG.md: they become the GitHub release notes, and the release workflow stops before building anything when they are missing or when notes are left under Unreleased.

Every OpenGizmo gadget has its own release workflow file, and they are kept the same apart from the gadget's name and module (chip), which sit in the `env` block at the top. When you change one, make the same change in the others.

Work on the `feature` branch; changes reach `develop` and then `main` one step at a time, only for a release.
